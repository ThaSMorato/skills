# Directions

Three directions are three answers to the brief, not three color schemes. The owner chooses better between real alternatives than when shown one design and asked to approve it.

## What varies
- **An established world**: the visual system is fixed. Vary the **structure**: what leads the screen, the navigation model, how the work area is split, which data is read first, the density. Derive five to seven structures from the content, the task and the behavior; keep the three that differ most.
- **A redesign**: the same, and each direction says which audit problems (`UA-N`) it solves.
- **No visual authority**: structure and visual language both vary. Before drawing, name the product in one sentence, its audience's real situation, and what this screen must prove. Name the category's usual page and its predictable opposite: both are ruts. Pick a color strategy before any color: **restrained** (tinted neutrals and one accent), **committed** (one strong color across a large part of the surface), or **full palette** (three or four roles). Light or dark is decided by one sentence about where and in what light the screen is used, not by the category.

In operate mode the visual language lends type, palette, density and at most one signature element; it never replaces the navigation model or the controls users already know.

## Each direction's contract
Before building it, write about 150 words, the same anatomy for all three:
- **Thesis**: the one idea, in a sentence.
- **First view**: the exact composition of what the user sees first, and where the primary action sits.
- **Structure**: the regions, what leads, how it adapts to a narrow screen.
- **Language**: type roles and scale, the color roles, density (from the design system, when there is one).
- **Risk**: what this direction gets wrong for someone, said honestly.

A contract that reads like a mood ("clean, modern, friendly") has not decided anything yet: rewrite it until a builder could not misread it. The contract is a working document: it never goes into the built code (comments, attributes, hidden text).

**Check the plan against the brief before building.** For each part ask: would a similar prompt for a different product land in the same place? If yes, it is a default, not a decision: change it and say what changed and why.

## The category-standard option
Always offer a fourth, quiet choice: **the category standard, done well**. When the owner takes it, ask for two or three products that set the bar, and build it to that bar at full quality.

## Building them
Equal effort and equal visual weight for the three; the owner compares them side by side. Use the brief's real content at realistic sizes. Content you have to invent (sample names, entries) is written at full quality and labeled as sample; never invent prices, customers, numbers or capabilities, and list for the owner what has to be replaced.

## Re-rolls
A direction is rebuilt only on a factual ground: it breaks the brief, it cannot be built with the project's components, a claim in it is false. A preference is answered by choosing among the three, or by combining parts of them. After two rebuilds in a row, stop and ask what quality is missing.
