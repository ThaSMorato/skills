# Additional review evidence
Tests assert the reason for errors (code/type/message or stable domain result), not merely that anything threw. Run the configured mutation tool incrementally on changed production files when available and permitted; report each actionable survivor with file, line, mutation, missing assertion/boundary and reproduction command. Mark equivalent mutants with a concrete reason. A missing tool is disclosed, never installed silently. Whole-suite mutation is report-only and owner-requested or scheduled CI; acceptance never runs it.

API docs: resolve OpenAPI refs, including composition and arrays; object schemas that need fields must expose properties directly or through valid composition. Do not flag valid scalar/array/ref-only schemas for lacking properties. Compare actual handler status codes with documented responses. Living-doc review maps changed feature contracts to the owning FDD and generated API reference.

Architecture/quality: guards, interceptors, pipes and filters delegate domain decisions to services. Apparent modularization (folders or interfaces with cycles, shared internals or mandatory lockstep changes) is a finding only with concrete coupling evidence. Same-database compensation deletes are suspect when the steps belong in one transaction; cite the partial-failure state and whether a single transaction is actually possible.

Security: public `NEXT_PUBLIC_*` secret-like variables require checking exposure and value provenance; a server env module imported by client-capable code needs the framework's server-only boundary. Sealed stateless cookies have no per-session revocation unless server-side state/key rotation/lifetime provides an explicit story. Refresh rotation consumes the old token atomically; concurrent refresh/BFF requests need a defined single-flight or bounded grace/reuse policy. Unknown users are verified against a dummy hash at comparable cost to avoid timing enumeration. Never log credentials or secrets into shell history.
