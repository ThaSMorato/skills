# Report levels and discovery
Classify every finding by its narrowest valid owner: `flow` for plugin behavior that generalizes across projects, `repo-skill` for local skills/guides/rules/CLAUDE.md/AGENTS.md and team conventions, `repo-code` for code/config defects. A team ticket format extends the general ticket skill in the repo without copying it. In doubt choose the lowest level that resolves the issue. Historical `project` findings are reclassified from their target file with the original tag retained as provenance; ambiguous ones stay unclassified, never become flow automatically.

Write report counts as `findings: {flow: N, repo-skill: N, repo-code: N}` and include `harness: claude | codex | unknown`, plugin version and report date. Group findings by level, then stop. Never offer to act on findings or edit plugin skills from a project. On a later explicit owner request, local changes go through the stage owning the file; flow findings go to `/tm-flow-report`.

After writing a report, call `scripts/report-registry.mjs add --repo <absolute repo> --report <absolute report> --date <ISO date> --version <plugin version> --harness <harness> --counts '<JSON counts>'`. The registry stores metadata, counts and paths only, never code or report content. Prefer `THASMORATO_REPORTS_FILE`, then `CLAUDE_PLUGIN_DATA/reports.json` when supplied by Claude, otherwise `~/.claude/thasmorato-skills/reports.json`, shared by both harnesses. If registration fails, keep the report and report the discovery failure.

With no paths `/tm-flow-report` reads `report-registry.mjs list`; explicit paths still work. Missing/moved repos and reports are marked missing and skipped without aborting; never guess their new location. Read only flow findings for synthesis; historical project/untagged findings are listed separately for classification, not included in flow totals. Compare measurements by `(plugin_version, harness)`; unknown stays separate.
